# 第 6 章 · 采购文件编制与合规审查 场景指南

## 1. 场景目标

Flask + DeepSeek + Dify 工作流主备双路由，集成 PyMuPDF 与百度 OCR；需求结构化提取、招标文件流式生成、字段级防幻觉校验、四块 42 项合规审查与 25 项避错专项审查。

## 2. 能力清单

- PDF/DOCX/TXT 与 300DPI 扫描件的混合文本提取
- 按 JSON Schema 抽取需求字段并逐项回指原文（check_field_in_source）
- 模板骨架 + 字段填充 + 章节级生成 + 全局一致性校验
- 关键字段正则防幻觉与审查结果行号锚点定位
- 67 项采购检查与分析维度中的 42 项合规 + 25 项避错规则

## 3. 环境准备

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env                       # 填入 DEEPSEEK / Dify / 百度 OCR 密钥
python app.py                              # http://localhost:5001
```

## 4. 核心模块索引

- `app.py`：/recognize_tender_info、/generate_tender、/review_tender
- `app.py::_validate_hallucination`：关键字段防幻觉校验
- `app.py::_sanitize_review_result`：审查结果行号锚点净化
- `docs/67项采购检查与分析维度完整清单.csv`：四块审查与避错规则明细
- `bid_collusion_workflow.yml`：Dify 工作流导入样例（第7章亦使用）

## 5. 演练步骤

1. 按第 3 节启动服务并确认健康检查通过。
2. 按 `examples/README.md` 中的示例调用本章核心接口。
3. 对照书中该章「实践案例」的界面截图核对返回结果。
4. 修改规则清单或提示词后重跑，观察结果差异；把本单位制度语料接入后再评测一次。

## 6. 验证点

- 返回结果是否带证据片段/行号锚点，能否回指到原文；
- 关键字段是否通过防幻觉校验，空白字段是否被标为「待确认」而非自动补值；
- 规则清单中的各项是否都有明确命中或未命中结论；
- 全过程是否留痕、结果是否可复现。

## 7. 常见问题

| 现象 | 排查方向 |
|---|---|
| 接口返回密钥错误 | 检查 `.env` 是否填写、变量名是否与 `.env.example` 一致 |
| 扫描件无文本 | 确认 OCR 服务已开通、扫描分辨率不低于 300 DPI |
| 生成结果出现旧项目信息 | 清空模板占位内容，启用防幻觉校验并人工复核 |
| 端口被占用 | 修改启动命令中的端口号，生产环境关闭 `debug=True` |
