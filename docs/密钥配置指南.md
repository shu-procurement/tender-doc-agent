# 密钥配置指南

> 适用仓库：`tender-doc-agent` ｜ 对应 第 6 章 采购文件编制与合规审查
> 本仓库**不含任何真实密钥**。所有 API Key、数据库口令与签名密钥均通过 `.env` 注入，源码只读取环境变量。

## 1. 三步配置法

```bash
# 第一步：复制模板（模板内全部是占位符，不含真实值）
cp .env.example .env

# 第二步：按下方字段表填入自己申请的值（用任意文本编辑器）

# 第三步：运行校验脚本，确认必填项齐全且占位符已替换
python3 scripts/check_env.py
```

校验脚本**只打印字段名与状态，不打印密钥值**；返回 `[OK]` 后再启动服务：

```bash
python app.py    # http://127.0.0.1:5001
```

## 3. 各平台申请入口与生成方法

### 3.1 大模型与工作流密钥

| 平台 | 入口 | 说明 |
|---|---|---|
| DeepSeek | https://platform.deepseek.com/api_keys | 创建 API Key，形如 `sk-...`；需账户有余额 |
| 智谱 BigModel | https://bigmodel.cn/usercenter/apikeys | 第 7 章前端使用，Anthropic Messages 协议 |
| Dify | https://dify.ai 或自建 Dify 控制台 | 导入 `bid_collusion_workflow.yml` 等工作流后，在工作流「访问 API」页生成 `app-...` 密钥 |
| 百度智能云 OCR | https://console.bce.baidu.com/ai/ | 创建文字识别应用，取得 API Key / Secret Key；仅扫描件解析需要 |

> 只需复现核心流程时，可**先只配置大模型密钥**：Dify 工作流与 OCR 均为可选增强，未配置时相关功能会给出明确提示，不影响其余模块运行。

### 3.2 本地随机密钥（无需申请）

`DJANGO_SECRET_KEY` / `FASTAPI_SECRET_KEY` / `FLASK_SECRET_KEY` 是本地签名密钥，用以下命令生成后填入即可，不要使用示例值：

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

### 3.3 数据库与邮件（可选）

- **MySQL**：建议创建只读账号 `procurement_ro`，仅授予 `SELECT`，避免 Text-to-SQL 越权；口令填入 `MYSQL_PASSWORD`。
- **邮件**：`EMAIL_HOST_PASSWORD` 填的是邮箱 **SMTP 授权码**（不是登录密码）。不配置时 Django 使用控制台后端，验证码打印在终端，不发送真实邮件；需真实发信时把 `EMAIL_BACKEND` 设为 `django.core.mail.backends.smtp.EmailBackend` 并补齐 `EMAIL_HOST` 等信息。

## 4. 安全红线

1. `.env` / `.env.local` 已被 `.gitignore` 排除，**绝不提交到 Git**，也不要改名后提交。
2. 密钥只写在环境变量里，**不要回填进 `app.py`、`config.py`、工作流 yml 或文档**。发布版源码已移除所有硬编码凭据，请勿改回旧工程包的写法。
3. 不要把密钥贴进聊天、截图、演示文稿、论文或录屏；调试日志中如出现密钥应立即清理。
4. 按最小权限申请：只读数据库账号、限额的模型 Key、独立的工作流 Key；不同环境使用不同密钥。
5. 密钥一旦意外公开，**立即到平台撤销并重新签发**，删除文件不足以挽回；公开仓库的历史提交同样视为已泄露。
6. 生产环境改用密钥管理服务或 CI/CD Secrets 注入，不要依赖本地 `.env`。

## 5. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 校验脚本报「仍是占位符」 | `.env` 里的值还是 `your-...` / `please-generate-a-random-string`，替换为自己申请的真实值 |
| 接口返回 401 / invalid api key | Key 填错、复制时带了空格或引号，或账户余额不足；用 `curl` 单独验证 Key 可用性 |
| Dify 报 workflow not found | 未导入工作流 yml，或用的是应用 Key 而非工作流 API Key |
| 浏览器控制台 CORS 报错 | 第 7 章把 `VITE_BIGMODEL_URL` 改为 `/api/bigmodel-anthropic`，走 Vite 代理 |
| 百度 OCR 报 token 失败 | AK/SK 填反，或未开通文字识别服务 |

完整部署流程见 `docs/场景指南.md` 与随书第 6 章「实践案例」；安全事件报告方式见 `SECURITY.md`。
